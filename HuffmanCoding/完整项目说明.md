## 💡 程序功能详解

### **功能1：初始化（菜单选项1）**

输入哈夫曼树的基础数据（字符和权值）

```
输入字符数量: 4
请依次输入 字符 权重 (例如 A 10):
A 5   ← 字符A，权值5
B 2   ← 字符B，权值2
C 9   ← 字符C，权值9
D 4   ← 字符D，权值4
```

**程序自动输出编码表：**
```
[哈夫曼编码表]
字符  权重  编码
A     5     10
B     2     001
C     9     0
D     4     011
```

### **功能2：编码（菜单选项2）**

将文本转换成二进制码

```
输入待编码字符串: ABCD
编码结果: 10001011001001
```

**工作原理**：
```
A → 10   (来自编码表)
B → 001
C → 0
D → 011
组合 → 10001011001001
```

### **功能3：译码（菜单选项3）**

将二进制码转换回原文本

```
输入二进制序列: 10001011001001
译码结果: ABCD
```

**工作原理**：
从根节点开始，按照二进制位走树
- 打到0走左子树，遇到1走右子树
- 到达叶子节点就输出一个字符

### 详细脚本

```
【讲稿开始】

各位老师同学，大家好！我今天汇报的是"哈夫曼编码与数据压缩"实验。

【第一部分：背景】
在计算机中，数据的存储和传输都需要消耗资源。
为了提高效率，科学家发明了数据压缩技术。
其中最经典的——就是今天的主角"哈夫曼编码"。

【第二部分：原理】
哈夫曼编码的核心思想是：
- 频繁出现的字符，用短编码表示（比如用"0"）
- 很少出现的字符，用长编码表示（比如用"001"）
这样，整体的数据长度就大大减少了。

我们来看一个具体例子...

【运行程序】
让我打开编译好的程序

【初始化阶段】
假设我们有4个字符：A、B、C、D
它们在文本中出现的频率分别是：A:5次，B:2次，C:9次，D:4次

我现在初始化这颗树...
（选择菜单1，输入上述数据）

程序自动为我生成了哈夫曼编码表：
- A编码为 "10"  （2位）
- B编码为 "001"（3位）
- C编码为 "0"   （1位）← 最频繁，编码最短！
- D编码为 "011"（3位）

【编码演示】
现在我有一段文本："ABCD"
让我用建好的编码表来压缩它...
（选择菜单2，输入"ABCD"）

原始数据："ABCD"，需要4个字符
编码结果："10001011001001"，只需14个比特位（约2字节）

这就是压缩的效果！

【译码演示】
现在的问题是，接收方怎么解出原来的文本？
我有一个编码的比特流："10001011001001"
用哈夫曼树从根走下去...
（选择菜单3，输入"10001011001001"）

译码结果："ABCD" ← 完全恢复！

【总结】
通过这个实验，我们看到：
1. 哈夫曼编码能有效压缩数据
2. 使用哈夫曼树能准确地编码和译码
3. 这个原理被广泛应用在 ZIP、MP3、JPEG 等领域

谢谢大家聆听，我的汇报完毕！

【讲稿结束】
```

## ⚠️ 已知局限

1. **中文输入的字符数量有限**
   - 限制在26个英文字母范围内较稳定
   - 建议用大写字母 (A-Z)

2. **权值范围**
   - 建议使用整数权值
   - 小数权值在演示时易产生舍入误差

3. **树深度限制**
   - 字符数越多，编码越长
   - 建议演示字符数在3-7个之间

4. **system() 函数兼容性**
   - Windows：`pause` 和 `cls` 正常工作
   - Linux：需要用 `read` 代替 `pause`，用 `clear` 代替 `cls`
   - 解决：直接在命令行运行，或修改代码
